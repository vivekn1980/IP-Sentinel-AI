# Security Policy & Architecture

## 🛡️ Defensive Security Principles

**IP Sentinel AI** is designed as a defensive cybersecurity, incident response, and attack surface discovery tool. Security and safety are enforced through strict technical architecture controls.

---

## 1. Ethical & Legal Use Disclaimer

- **Authorized Use Only**: This software is intended strictly for:
  - Security analysts auditing infrastructure they own or manage.
  - Authorized security professionals operating within an agreed penetration testing scope or bug bounty scope.
  - Educational and defensive cybersecurity research.
- **Prohibited Use**: You may NOT use IP Sentinel AI for unauthorized network attacks, harassment, disruption, or scanning targets without explicit permission.
- **Limitation of Liability**: The authors and contributors assume no liability and are not responsible for any misuse, damage, or legal consequences caused by this software.

---

## 2. Network Operations & Probing Safety

- **Passive by Default**: The majority of IP Sentinel AI operations (DNS resolution, RDAP bootstrap queries, GeoIP/ASN lookups, Certificate Transparency log searches, and Passive DNS archives) are 100% passive. No traffic reaches the target origin server during passive lookups.
- **Standard Protocol Handshakes**: Active verification features (such as SSL Certificate inspection on port 443 and lightweight banner extraction) only perform standard RFC-compliant TCP handshakes and `HEAD` requests.
- **Zero Exploit Payloads**: IP Sentinel AI **never** executes exploit payloads, brute-force attacks, fuzzing, denial-of-service tests, or vulnerability injection scripts.

---

## 3. Command Injection Immunity

- **Zero OS Subprocesses**: User-supplied IPs and domains are parsed and sanitized using Python's built-in `ipaddress` and `urllib.parse` standard libraries.
- The application **never** shells out to OS commands (`ping`, `nslookup`, `traceroute`, `nmap`) via user-influenced command strings.

---

## 4. Credential Protection & Secret Scrubbing

- **SecretStore Abstraction**: API keys (AbuseIPDB, VirusTotal, AlienVault OTX) are stored in `%LOCALAPPDATA%\IPSentinelAI\credentials.json` or operating system environment variables (`IPSENTINEL_KEY_*`).
- **Log Redaction**: The internal `QtSignalLogger` automatically scrubs sensitive keys, tokens, and authorization headers before printing to logs or displaying in UI consoles.
- **Masked Input Fields**: API key inputs in the Settings view are masked (`QLineEdit.Password`).

---

## 5. Report Injection Protection

- **Template Escaping**: HTML reports generated by `HTMLReportGenerator` use strict Jinja2 autoescaping (`autoescape=True`) to eliminate any risk of Stored XSS or HTML injection from malicious RDAP/DNS strings.

---

## 6. Reporting a Vulnerability

If you discover a security vulnerability within IP Sentinel AI:
1. Please do not open a public issue.
2. Submit your findings directly via GitHub Security Advisories or contact the maintainer: **Vivek Nigam**.
3. We will acknowledge receipt within 48 hours and work with you on a coordinated fix.
